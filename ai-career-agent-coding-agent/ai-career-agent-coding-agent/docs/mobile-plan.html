How it's built (and why it can't break the website)

Screens→Controllers→Repositories→API client→existing jobiest.com backend
LayerDecisionWhy
FrameworkFlutter + Material 3, single codebase, Android + iOSReal native UI (no WebView), one codebase to maintain
Stateprovider + explicit Loading/Data/Empty/Error statesSmall, official, boring — every screen handles every state
AuthSupabase session in device secure storage (Keystore/Keychain); MFA nativeSame provider as the website; tokens never in plain storage or logs
BackendFrozen after bc0ca35 — app consumes existing APIs onlyThe website cannot regress; all entitlements/limits stay server-side
BuildsGitHub Actions: analyze → test → APK artifact on every pushEnds the toolchain-wipe loop; you can download any build from GitHub
Releasev2.0.0 · com.jobiest.app · your existing keystoreUpdates the existing Play listing; no new accounts needed
