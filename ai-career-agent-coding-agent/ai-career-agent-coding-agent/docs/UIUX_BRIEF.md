# AI Career Agent, UI/UX Brief

## 1. Product Personality

The interface should feel:
- Professional.
- Calm.
- Intelligent.
- Trustworthy.
- Fast.
- Minimal.
- Career-focused.

Avoid a noisy "AI robot" aesthetic.

## 2. Core Navigation

Desktop:
- Overview
- Opportunities
- Applications
- Documents
- Email & Interviews
- Agent
- Profile
- Settings

Mobile:
- Home
- Jobs
- Applications
- Agent
- More

## 3. Dashboard

Top:
- Greeting.
- Agent status.
- Pause/resume control.

Metrics:
- Applications today.
- Jobs discovered.
- Shortlisted.
- Interviews.
- Response rate.

Main:
- Recommended opportunities.
- Recent applications.
- Agent activity.

## 4. Onboarding

Use a progressive wizard.

### Screen 1
"What do you do?"

Role selector with custom role.

### Screen 2
"Where do you want to work?"

Remote/hybrid/onsite, locations.

### Screen 3
"What work are you targeting?"

Multiple roles and keywords.

### Screen 4
"Add your professional background."

CV upload + manual profile.

### Screen 5
"Connect your email."

Google OAuth.

### Screen 6
"How much control should your agent have?"

Draft / Assist / Approval / Auto.

### Screen 7
"Set your daily target."

Default: 10, editable.

## 5. Opportunity Card

Display:
- Company.
- Role.
- Location.
- Match score.
- Why it matches.
- Key requirements.
- Missing/uncertain requirements.
- Salary if available.
- Source.
- Application deadline if available.

Actions:
- View.
- Save.
- Skip.
- Apply.
- Ask agent.

## 6. Application Detail

Sections:
- Job.
- Match analysis.
- Personalized CV.
- Cover letter.
- Answers.
- Submission timeline.
- Email events.
- Audit log.

## 7. Agent Activity

Live event feed:

```text
10:01, Found 42 new jobs
10:04, Removed 11 duplicates
10:06, Scored 31 opportunities
10:12, Shortlisted 12
10:17, Generated application for Company A
10:18, Submitted application
```

## 8. Trust UI

Every AI-generated item should have:
- "Based on your profile" indicator.
- Source/fact trace where useful.
- Warning when information is uncertain.
- Edit control.

## 9. Visual Hierarchy

Use:
- Large readable headings.
- Compact cards.
- Clear status badges.
- Strong whitespace.
- Consistent spacing.
- Accessible contrast.
- Keyboard navigation.

## 10. Empty States

Examples:
"No applications yet. Activate your agent to begin."

"No interviews yet. We'll monitor your connected inbox."

"No jobs match your current filters. Broaden your preferences?"

## 11. Error States

Never say only "Something went wrong."

Show:
- What happened.
- Whether anything was submitted.
- What the user needs to do.
- Retry option.

## 12. Responsive Design

The entire product must work on:
- Mobile.
- Tablet.
- Desktop.

Application review should be especially good on mobile.

## 13. Accessibility

Target WCAG 2.2 AA principles:
- Semantic HTML.
- Keyboard access.
- Focus states.
- Labels.
- Screen-reader support.
- Reduced-motion support.
